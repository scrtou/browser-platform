# 管理页面 UI 重构说明

[文档导航](README.md) · [管理面功能规格](specs/proxy-environment/management.md) · [R6G 工作项](work-items/R6G-2026-09-20-management-ui-redesign.md)

状态：**首版已于 2026-09-20 由 R6H 部署；用户反馈的大功能 Tab 第二版已以 Adapter `fe4e13c4…` 部署，自动化与服务器复核通过，等待 Mac/Trilium 重新验收。** 本文规定 `/manage/` 的视觉与信息架构重构；功能、权限、安全和生命周期契约仍以管理面规格为准。

后续用户提出增加“网络代理”Tab、将浏览器关键配置改为模板下拉并重设计入口首页；这些属于尚未实施的 [R7 方案](browser-workspace-plan.md)，不属于本文已部署的 R6G/R6H 页面能力。

## 1. 背景与目标

当前管理页把浏览器状态、入口、健康、网络、环境、编辑表单和危险操作集中在九列表格中，并把账号操作继续堆叠在第二张表格里。功能可以使用，但在目标 Mac/Trilium 的 1280×800 视区中横向信息过密，表单控件宽度不一致，常用信息、低频高级配置和破坏性操作缺少清晰层级。

本次重构目标：

1. 在 1280×800 的 Trilium WebView 和普通桌面浏览器中，不依赖横向滚动即可识别每个浏览器的名称、运行/启用状态、健康、入口、网络和主要操作。
2. 把高频操作与代理、策略摘要、归档删除等低频或高风险操作分层；不能用颜色作为唯一状态提示。
3. 让表单字段具有可见标签、辅助说明、统一间距和明确提交范围，减少误操作。
4. 保持服务端渲染、无 JavaScript、无外部字体/图片/CDN，在资源加载失败或严格 CSP 下仍完整可用。
5. 保持现有权限、CSRF、重新认证、能力门控、字段名、路由和后端副作用不变。

非目标：不新增管理能力，不改变登录页或浏览器会话页，不改 API/JSON，不引入前端构建链，不借 UI 重构重新解释现有验收结论。

## 2. 必须保持的契约

- 页面仍由 `adapter/internal/httpapi/manage.go` 的 Go `html/template` 生成，所有动态值继续由模板自动转义。
- 不加载外部资源，不添加内联脚本、事件处理器或客户端状态；CSS 保持内嵌且不包含用户数据。
- 所有现有 `form` 的 `method`、`action`、隐藏 `csrf`、`action`、`revision`、`draft_id` 和输入字段 `name` 保持不变。
- 可选能力继续由 `CreateDelete`、`ProxyDrafts`、`JobsEnabled` 等服务端条件决定；能力关闭时既不展示入口，原端点也继续拒绝调用。
- 账号角色、Profile 授权、最近确认密码、停用/启用、安全关闭、代理应用、DIRECT、归档删除的条件不变。
- 页面继续显示固定入口的完整 URL；敏感值、密码散列、Session URL、Cookie、代理密码和授权参数不得进入 HTML。
- 保留现有可被测试和运维识别的中文操作文案，例如“新增浏览器”“安全关闭”“归档并删除”“确认密码”“新增与归档删除尚未启用”。

## 3. 信息架构

页面使用公共顶栏、反馈区和 Tab 导航；每次只渲染一个功能面板，不再纵向堆叠三个大功能。以下功能内容分别归入对应 Tab：

1. **顶栏**：产品标题“远程浏览器管理”、管理员身份和简短说明；右侧放返回首页、修改密码、JSON 等次级链接以及退出登录。
2. **反馈区**：已知 `notice` 作为具备 `role=status` 的反馈条，靠近页面顶端；未知 notice 仍不回显。
3. **浏览器区**：标题、数量/状态概览；新增浏览器表单在独立面板内，仅在能力启用时显示。
4. **浏览器卡片列表**：每个 Profile 一张卡片，不使用九列桌面表格。
5. **自定义指纹作业区**：仅能力启用时出现；提交表单和历史结果分开，历史在窄屏可自然换行或局部滚动。
6. **访问账号区**：账号状态与授权优先，密码重置、启停、角色变更放在明确的账号操作区；新增账号使用独立面板。
7. **页脚工具区**：只保留必要说明和版本/生成时间，不重复主要导航。

### 3.0 功能 Tab（用户反馈修订）

- 三个导航项为“浏览器”“指纹作业”“访问账号”，使用 `/manage/?tab=browsers|jobs|accounts` 的服务端导航；默认及未知值回到浏览器页。
- 指纹作业能力不可用时隐藏该导航项，直接请求 jobs 安全回到浏览器页；其他权限和能力条件不变。
- 使用原生导航链接与 `aria-current=page` 表示选中项，不伪装成需要方向键行为的 ARIA tab widget。键盘 Tab/Enter、刷新、前进后退与直接链接均可用，无 JavaScript。
- POST 后浏览器操作回浏览器页，作业和账号操作分别回 jobs/accounts；不信任客户端任意返回 URL。旧浏览器 notice URL 保持兼容。
- 公共顶栏提供“确认密码”链接，并以固定白名单当前 Tab 构造 reauth 的 next，使网络、删除与账号操作均能发现入口。
- Tab 导航窄屏可换行或局部滚动，页面本身不横向溢出。切换页面不自动提交尚未保存的表单。

### 3.1 浏览器卡片

每张卡片包含：

- 卡片头：显示名称、可选 Profile ID、启用/停用徽标、运行状态、修订号。
- 入口块：完整可点击 URL 和已分配账号；URL 允许断行，不能撑破卡片。
- 概览网格：健康及采样时间、网络、显示/语言/时区、环境产物、Home。未知、未观测、过期和阻塞状态保留文本。
- 常用设置：名称和起始页编辑表单，提交按钮明确为“保存设置”。
- 生命周期操作：启用/停用和安全关闭彼此分开；停用与关闭使用警示样式但不能伪装为归档删除。
- 高级网络：代理草稿、探针、应用和切回 DIRECT 放入原生 `details`；保持当前条件渲染和重新认证要求。
- 危险操作：归档删除单独位于带边界的危险区，幂等键有可见标签；不新增未经后端支持的确认步骤。

摘要不可用时，卡片仍显示名称和入口，并以文本明确“摘要暂不可用”，不能产生列错位。

### 3.2 表单规范

- 文本、URL、密码、选择框和 textarea 都使用显式 `label`；placeholder 只作示例，不承担字段名称。
- 一组提交按钮只提交与其同一表单中的字段；不能为了布局把互不相关的现有表单合并。
- 字段默认占满所在容器；短字段通过响应式网格并排，窄屏自动单列。
- 帮助文字放在字段组附近，尤其说明幂等键、下一代次生效、近期确认密码和 Home 归档语义。
- 浏览器原生校验属性与现有 `required`、长度、pattern、autocomplete 保持。

## 4. 视觉系统

只使用 CSS 自定义属性和系统字体：

- 页面背景使用低饱和冷灰，内容卡片使用白色；正文保持深色高对比。
- 主色使用克制的蓝色；成功、警告、危险分别使用绿、琥珀、红，并同时附带文字标签。
- 统一圆角、1px 边框和轻微阴影；不使用大面积渐变、玻璃拟态或装饰动画。
- 主按钮、次按钮、文本按钮和危险按钮具有明确层级；所有可交互元素提供可见的 `:focus-visible` 轮廓。
- 正文默认 15–16px，元信息不小于 12px；触控目标尽量达到 40px 高。
- URL、摘要和标识符使用可换行策略；不得因长内容扩展页面宽度。

建议断点：

- `>= 1100px`：浏览器卡片概览可使用 3–4 列网格，账号表保持完整布局。
- `700–1099px`：概览缩为 2 列，编辑与操作区换行；适配 1280×800 Trilium 的实际内容宽度。
- `< 700px`：所有主要表单单列，表格放入有边界的局部横向滚动容器；页面本身不横向滚动。

支持 `prefers-reduced-motion` 和系统深色偏好不是本次完成条件；若实现深色模式，必须保持状态和表单对比度，并不能增加外部资源或脚本。

## 5. 可访问性与安全

- 页面使用 `header`、`main`、`section`、`footer`，标题级别连续；每个表单有可感知的名称。
- 状态徽标必须包含文字；链接与按钮文案描述动作结果，不能只写“操作”。
- 键盘可依 DOM 顺序完成所有操作；折叠内容使用原生 `details/summary`。
- 反馈条使用合适的 ARIA role，但不把普通说明设为实时区域。
- 不使用 `target=_blank`、复制脚本、客户端模板或把敏感字段写入 data 属性。
- CSS 不改变 `hidden`/条件渲染的安全含义；视觉隐藏不能代替服务端授权。

## 6. 实现边界

主要改动限于 `adapter/internal/httpapi/manage.go` 的 `manageTemplate`，以及支持白名单 Tab 选择和 POST 返回所属 Tab 的最小页面 handler/重定向调整；补充 DOM/导航契约测试。不修改业务 handler 的副作用、Profile 服务、账号存储、路由、JSON、控制器、配置和生产部署文件。

允许为了语义和布局增加包装元素、CSS class、`aria-*`、`role`、可见 label、caption 和辅助文字；不允许修改业务条件或引入新 POST 参数。对模板结构的自动化测试应验证稳定的功能契约，避免绑定纯装饰 class。

## 7. 验收标准

### 自动化

- `gofmt` 对相关 Go 文件无差异。
- `go test ./internal/httpapi ./internal/access` 通过；条件允许时执行 Adapter 全量 `go test ./...` 与 `go vet ./...`。
- 现有管理面测试继续覆盖：未登录/非管理员拒绝、能力门控、CSRF、表单动作、notice 不回显、敏感字段不泄漏。
- 新增或调整断言确认：语义主区域存在；浏览器卡片、可见 label、危险区和响应式 viewport 存在；所有关键路由与字段名保留。
- Tab 默认/显式选择、非选中面板不渲染、未知值和能力关闭回退、对应 POST 返回位置、确认密码返回路径均需自动化覆盖；现有安全断言仍须在对应功能页验证。
- `git diff --check` 和文档相对链接检查通过。

### 视觉与交互

- 本地以至少一个包含浏览器、账号、notice 和可选能力的代表性页面检查 1280×800 与窄屏布局；若没有可安全访问的测试实例，可用单元测试渲染结果或隔离 fixture，不操作生产 Home/Session。
- 最终生产视觉结论必须由部署后的真实 Mac/Trilium 复测给出；代码与本地渲染通过不能写成生产或目标客户端已经通过。
- 复测重点：页面无整体横向滚动，浏览器关键信息首屏可辨，名称/起始页修改、确认密码链接、账号分配和安全关闭入口可发现，高风险操作与普通保存有明显区隔。

## 8. 发布与回退

R6G 的交付范围只包含源码、自动化和隔离检查，不自动部署生产；后续 R6H 已按用户授权完成首版和 Tab 修订版发布。UI 随 Adapter 二进制发布，不改变持久状态格式；回退方式是恢复前一 Adapter 二进制。发布只重启 Adapter，并再次确认 Personal/Work 的 Home、Session、运行绑定和账号表未变。目标 Mac/Trilium 视觉仍须由用户反馈，不因自动化或服务器检查通过而宣布完成。
