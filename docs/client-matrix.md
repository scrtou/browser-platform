# 客户端验收矩阵

[客户端操作](trilium-client.md) · [R4A 验收](../infra/sealskin/client-migration-acceptance-2026-09-14.md) · [开发计划](roadmap.md#r4)

本矩阵截至 2026-09-16。目标为 Trilium 0.105.0 / macOS 15.1 (24B83)，本机 1280×800、正常显示、macOS 系统中文输入法。用户未提供系统缩放选项或本机 DPR；不能从分辨率或远端报告推断。

本轮使用独立 QA Home 和临时账号，入口见 [客户端说明](trilium-client.md#r4b-独立实机验收)。用户已提交 r7 的 17:48 UTC 报告并确认基础交互；r9 修复了远端原生窗口和桌面客户区，但用户随后反馈固定画面在 Mac/Trilium 视区仍有留边，同时确认五个按钮可点击、实际图片预览可见。问题定位为固定 16:9 画面使用 `contain` 缩放；新的 `fill-r10` 客户端候选保留 r9 screen/DPR 和 QA Home，将画面与输入层映射到整个客户端视区。用户现已确认 fill-r10 视觉上铺满且点击正常；窄视区的非等比缩放使字体显得细长，作为固定分辨率取舍保留；r9/fill-r10 Linux 复测通过，测试资源继续保留供 R4B 收尾，尚未清理。

Linux 的尺寸/输入/导航/文件/断线结果已在 r9 复测；原生截图还新增实际预览和像素对照。大文本、反向复制与取消/异常矩阵沿用 R4A 明确版本的历史证据，本轮没有重跑全部剪贴板边界。

## 实机记录方法

使用专用 QA Home 与短期测试会话。由运维准备 [观测页面](../infra/sealskin/checks/client-fixture.html)，页面只写测试 nonce；不在公开报告保存真实 Cookie、登录内容或授权 Session URL。

1. 记录 Trilium、Electron、macOS 版本，显示器型号/缩放选项、Trilium 窗口大小、输入法名称和键盘布局。
2. 在 QA 页面按当前尺寸点击五个按钮，再改变 Trilium 窗口和系统显示缩放重复；用页面「复制验收资料（F9）」保存远端 screen、DPR、outer/inner 和坐标。Mac 本机参数另行记录，该页面位于远端，不能测量本机 DPR。
3. 用实际输入法输入 `繁體中文😀𠮷`，操作候选、替换、取消；确认前后已有文字未丢失。分别验证后退/前进、新建/切换/关闭测试标签页与滚动。
4. 断开客户端网络后恢复并重载，记录提示、恢复操作和数据。不要停止生产 Worker 或重启主机来代替该项。
5. 在 Mac 选择测试 PNG 并从 Finder 拖入，运维核对远程 QA Home 的摘要。截图测试先点击「截圖貼上區」再按 ⌘V，确认页面预览内容，并用 F9 记录实际 MIME、字节数、尺寸、摘要和 paste 可信标记；仅桥接成功提示不能填完整通过。文字大文本、Copy 菜单、同值、迟到、焦点变化和取消分别记录。
6. 在 QA 会话验证浏览器退出、代理故障的恢复提示，按实际结果填写通过/失败/不支持/未测。只在适用分项通过后进入生产切换步骤。

记录至少包含：日期、客户端/服务端版本、QA Home/环境修订、每项操作和结果、观测报告摘要、未测项目及原因。R4B 的维护与真实站点登录证据另行登记；本表不授权停止真实会话。
