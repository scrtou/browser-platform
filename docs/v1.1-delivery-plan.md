# 1.1 版本交付计划：三引擎镜像解耦

状态：计划中，未开始实施。归属工作项：[R7H 三引擎镜像解耦](work-items/R7H-2026-10-04-engine-image-decoupling.md)。

## 背景与目标

1.0 的三种浏览器在运行时是独立容器、独立进程和独立 Home，但构建层仍存在不必要的耦合：`infra/environment-engines/build-images.py` 将 Firefox 和 Chromix 从已包含 Camoufox 的 `r10-managed-desktop-candidate` 镜像继续构建。因此 Chromix、Firefox 镜像中会保留未使用的 `/opt/camoufox`、Camoufox Python 环境和相关字体；这增加了下载、导入、存储和安全审计成本，也让一个引擎的底层变化影响其他引擎。

1.1 的目标是建立不含任何浏览器引擎的公共桌面与显示基础镜像，再从同一份固定基础分别构建 Camoufox、Chromix 和 Firefox。每个最终镜像只能包含对应引擎及明确批准的公共运行时；三引擎的启动器、浏览器二进制、设备产物、字体和升级锁定保持独立。1.0 的固定镜像、发布材料、现有 Home 和回退路径保持不变，1.1 以新摘要和新验收报告发布。

## 现状基线与约束

- 当前基线由 `infra/environment-engines/build-images.py` 的 `BASES`、三个 `Dockerfile.*`、`infra/chromix/build-image.py` 及各自的发布锁文件共同决定。
- 当前生产已通过公网 HTTPS、三引擎画面/输入/停止删除验收；这些行为契约不能因拆层改变。
- 新镜像不得覆盖、移动或重写 v1.0 镜像标签；所有新目标使用不可变完整 digest 和新的输入摘要。
- 现有 Camoufox 设备产物、Chromix seed、Firefox 原生配置、网络/显示认证、正常关闭和客户端输入边界必须分别保留。已有 Home 不因升级自动换引擎或重新生成身份。
- 目标是消除跨引擎文件和构建依赖，并实测报告节省的唯一磁盘层；在剖析完成前不承诺具体 GiB 数字。

## 分阶段工作

### H1：契约盘点与中立基础镜像设计

盘点三个引擎当前实际需要的 X11、Openbox、Selkies、音视频、字体、代理/认证辅助程序、Python 工具、退出层和安全配置。将内容分为公共桌面层、引擎层和 QA 依赖，明确哪些字体是设备产物依赖，哪些只能放入对应引擎镜像。为公共层建立单独版本和发布锁，禁止出现 Camoufox、Chromix 或 Firefox 可执行文件、浏览器 profile 和引擎专属 Python 路径。

完成条件：有中立基础镜像清单、文件归属表、镜像 digest/许可证清单和迁移/回退说明；对 v1.0 运行契约没有未决歧义。

### H2：分别构建三个引擎镜像

新增公共桌面镜像构建入口，修改 `build-images.py`、`build-client-resolution.py`、`build-keyboard-order.py` 及相关 Dockerfile，使三个引擎都以同一中立 digest 为根层，再各自加入浏览器、启动器、锁文件和设备依赖。将原来依赖 `/opt/camoufox-python` 的公共工具迁移到命名明确的公共运行时路径，或证明该路径确实只属于 Camoufox 后再保留在引擎层。构建使用离线、精确 digest、输入摘要和不可移动标签。

完成条件：三份镜像可单独构建；镜像配置的 engine label、启动入口、版本锁和 native-targets 映射互相一致；Chromix/Firefox 文件系统中没有 Camoufox 目录、二进制、启动器或仅供 Camoufox 的运行库，Camoufox 镜像中也没有不需要的其他浏览器二进制。

### H3：镜像、运行和升级验收

先做静态检查：层归属、文件清单、ELF/脚本引用、进程树、容器 label、镜像摘要和实际磁盘占用。再用独立 QA 资源逐引擎验证冷启动、Google 起始页、真实远程画面、鼠标/键盘输入、受管理网络、显示 Cookie、正常关闭、Home 锁和恢复。覆盖服务重启、镜像缺文件、错引擎镜像、旧 Home 误切换和摘要漂移拒绝。

完成条件：三引擎各有完整 PASS 报告；负向检查证明引擎不会启动另一个浏览器；旧 v1.0 实例和 1.1 实例可区分并可按文档回退；镜像总占用、各引擎独有层和共享层均有去重后的实测表。

### H4：发布、部署和运维切换

生成 1.1 程序/镜像清单、SHA-256、下载与导入说明、升级前备份和回退步骤。部署器只接受新清单中的精确镜像，保留 v1.0 回退引用。说明现有浏览器不自动重建，只有新建浏览器或明确迁移时才选择 1.1 引擎；升级失败保留 Home、设备产物和审计记录。

完成条件：在独立目录完成从下载、校验、导入、安装到公网 HTTPS 管理的演练；文档、工作项、验收索引、进度和路线图同步；未完成的引擎或客户端范围保持明确的待验证状态。

## 验收门槛

1. 三个最终镜像共享公共桌面层，但没有跨引擎浏览器文件或启动依赖。
2. 三引擎均通过现有网络、显示认证、输入、关闭、恢复和 Home 隔离验收；新增的镜像纯度和错误镜像拒绝检查通过。
3. 1.0 线上部署、域名/Caddy 配置、现有账号、Home、Session 和回退材料不被修改；迁移是可选择、可审计、可回退的操作。
4. 发布材料包含完整 digest、输入摘要、许可证/来源和去重后的容量对比；不能只用 `docker images` 的虚拟大小宣称节省。
5. 1.1 未达到全部门槛前，保持计划中，不替换当前 1.0 镜像或扩大现有验收结论。

## 不在本计划内

本计划不重做指纹能力 F1～F4，不改变账号/域名/Caddy 契约，不重新设计浏览器业务 API，不承诺音频、Trilium/macOS 或第三方网站行为超出现有验收范围。任何新的引擎能力另立工作项。
