# DEV-035 · Session 交接仍向客户端返回后端能力

状态：已解决（代码与隔离 QA，未部署生产）。工作项：[R5D](../work-items/R5D-2026-09-14-entry-authentication.md)。

预期：一次性交接只发放网关自己的短期显示 Cookie，后端 Session 能力只保存在网关内存，经受验证的私有通道交给控制器。

源码事实：候选 1 的 `Grant` 返回一次性 ticket，但 `accept` 随后又重定向到带原 `access_token` 的 target；后续代理依赖浏览器持有后端 Cookie。原控制测试只检查第一次跳转，遗漏兑换响应。另一个同主体/同 Session 的交接会撤销浏览器原有显示授权，可能关闭先前标签页。

处理选择：修复实现。兑换后仅返回干净的当前 Session 地址，私有后端能力保留在该显示授权中，由代理加入内部认证请求头；剔除客户端伪造的同名头和后端认证 Cookie，不把后端 Set-Cookie 返回客户端。内置 Caddy 在转发 Worker 前删除内部认证头。同一登录、Profile、Session 和后端能力的重复打开复用显示授权；不同登录或绑定不能复用。

私有头路径必须继续执行原 `session_gate`，不能因绕过旧 token-to-Cookie 路由而跳过一致性门槛。候选 2 包保留为中间构建，补齐此检查后固定新候选；控制测试需证明凭据正确但一致性证据缺失时仍拒绝。

须验证：兑换响应/Location/Cookie 无后端能力；私有认证正常、伪造值和能力查询参数拒绝；重放、跨主体、重复打开保持现有升级连接以及注销/到期仍关闭连接。以真实浏览器和私有后端验证，不以单元测试替代。

2026-09-15 实际 Selkies 边界：第九轮真实表单、Cookie、干净交接、二进制帧和跨 Session HTTP/WS 拒绝已通过。再次打开完整画面时，固定上游 `selkies.py` 会给旧 primary 发送 `KILL`，再以 1000 / `Superseded by new client` 关闭连接；它只保留一个 primary 控制端。原 QA 将这种显示接管误等同于网关撤销，失败证据保留。此次不扩展为多控制端显示：验收继续要求重复**交接本身**保留原 Cookie/连接，随后另验完整画面的上游接管及 Worker/Home/Session 不变。用可观测的上游 KILL 事件区分接管和授权撤销，不把旧连接已经关闭当作注销成功的唯一证据。

第 10/11 轮用页面路由拦截隔离交接，但仍载入第二个 Selkies；新增关闭事件证据确认旧连接收到了 KILL 和 1000 接管原因。最终交接隔离方式改为复制同一登录 Cookie 到临时无脚本上下文，以真实“继续”按钮提交表单并接收真实后端文档。完整脚本/画面与接管路径仍单独执行；这项辅助检查不使用替代响应来证明授权。

2026-09-15 最终验证：`client-qa-13/` 的干净兑换、重复交接保留原 Cookie/连接、完整 Selkies 接管保持代次、重放/到期拒绝以及注销/禁用/到期/绑定变化关闭真实画面全部通过。ticket 到期由 CDP 在真实 POST 响应阶段截住 303 后验证。C3 的私有头路径仍执行 `session_gate`，正确能力但缺一致性证据拒绝的控制测试通过；QA 未启用 coherence，R5C3 的实际策略矩阵保持独立版本范围。完整结果见 [最终验收](../../infra/sealskin/entry-authentication-acceptance-2026-09-15.md)。
