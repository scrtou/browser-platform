# DEV-009 · 备份未覆盖实际服务密钥路径

状态：已解决（代码/QA，本次未部署生产）。发现日期：2026-09-14。所属工作项：[R5B](../work-items/R5B-2026-09-14-secret-store.md)。

规格 50.3 要求备份包含恢复所需的控制状态和解密材料。核对固定上游 `settings.py` 与独立 QA 的目录后发现：服务私钥和代理 TLS 证书位于 `/config/ssl/`，旧 `backup-home.py control-state` 却从传入的 `/config/.config/sealskin` 的上一层查找 `ssl`，即 `/config/.config/ssl/`，缺失时静默跳过。新加密工具的初始草稿沿用了这个路径，并尚未包含 Adapter 配置所引用的独立客户端私钥和服务公钥。

选择修复实现：旧工具修正实际 SSL 路径；新加密工具核对默认部署目录，必须包含实际 `ssl`、Adapter 密钥、控制端管理员恢复材料及必要授权元数据，缺少必要文件时拒绝。加密包的验证和恢复测试须逐项核对这些材料；实际 S05 演练还须用恢复的服务身份和凭据启动 QA 浏览器。

影响：旧控制状态归档不能据此认定含有服务 SSL 私钥。此前 R2 仅完成隔离演练，真实 Home/生产灾备仍未验收，本修复不扩大旧报告范围。历史报告保留原结果并补充此限制。

证据：`infra/sealskin/runtime/r5b-secret-store-2026-09-14/` 内的源码核对与后续备份验证。公开记录不保存密钥内容。最终验收：[R5B](../../infra/sealskin/secret-store-acceptance-2026-09-14.md) 的 28 项加密备份测试及新控制目录恢复通过：实际服务/Adapter 身份、固定产物、凭据和浏览器数据可用，备份后的撤销仍生效。管理员 bootstrap 文件已离线保存时可显式指定私有恢复文件；缺失必要材料或 journal 均拒绝，不伪造空状态。
