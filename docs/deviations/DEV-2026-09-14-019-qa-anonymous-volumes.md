# DEV-019 · 公开 QA 记录器遗留匿名卷

状态：已解决（工具修复、空卷清理及恢复清单；旧映射缺失事实保留）。关联工作项：[R5C2](../work-items/R5C2-2026-09-14-approved-dns-ttl.md)。

预期：专属 QA 记录器结束后清理其容器及临时卷；不删除其他工作或真实 Home 的数据。清理记录必须区分活动资源、明确归属的卷和无法归属的遗留物。

实际：收尾核对发现部分记录器复用的 LinuxServer 镜像声明了 `/config`、`/storage` 卷。工具用 `docker rm` 删除容器时未加 `-v`，也未保存完整 Mounts；因此“QA 容器为零”不能证明匿名卷全部清理。最终公开抓包内容、DNS/浏览器结果不受影响，但资源收尾尚未完成。当前卷清单、实际挂载快照及尚可取得的 Docker 事件保存于被忽略的 `runtime/r5c2-dns-ttl-2026-09-14/public-volume-*.json` 与 `public-docker-recent-events-1.jsonl`。

处理选择：补齐工具的精确 Mounts 留证与带卷删除；检查原始证据和 Docker 事件，逐个核对卷是否仍被容器引用。证据不足的卷先保持原样，不按时间范围或匿名名称批量删除；后续核对实际内容及其他引用，明确保留或清理决定。产品网络策略和 DNS 验收条件保持，尚未完成的清理不得写成全部通过。

工具已补保存完整容器/Mounts，并使用精确 ID 的 `docker rm -v`；通用 QA 清理器同样保留挂载证据并删除其匿名卷。修复只影响测试资源回收，不改变 DNS、浏览器或抓包内容。

最终复核：120 个空卷全部移除，其中 10 个另有精确历史挂载/事件映射、110 个按下述空卷决定处理；362 个此前已有卷保持。`public-volume-cleanup-1.json` 为 PASS，恢复清单位于 `public-empty-volume-restore-plan.json`。独立网桥检查再次通过四项真实帧场景，三个测试容器的六个匿名卷均确认随容器消失，证据为 `bridge-wire-cleanup-checks-3/`。工具说明、偏差索引、工作项和验收已同步。

后续只读核对：本次公开 QA 时段内的 120 个候选卷实际均为空目录，现有四个生产容器和保留的权威 DNS 均未引用它们。Docker 只保留最近 256 个事件，不能伪造已经丢失的旧容器映射。对缺少旧映射的空卷采用单独的可逆清理决定：保存完整 volume inspect 和按原名称/驱动/标签/选项重建空卷的恢复清单，逐个复核仍无引用且仍为空后，用准确名称执行不带强制参数的删除。不会将该方法用于含数据的卷，也不触碰本次时段之前的卷。这里增加了空卷的恢复路径，没有把缺失的历史映射写成已取得。
