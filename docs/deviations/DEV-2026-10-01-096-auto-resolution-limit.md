# DEV-096 · 自动分辨率请求超过虚拟屏幕上限

关联：[R6N](../work-items/R6N-2026-10-01-auto-resolution.md)。状态：已解决并部署，选择修复实现；不降低 3840×2160 上限验收要求。

候选要求超大客户端按比例限制到虚拟屏幕上限。实测 2560×1440、客户端 DPR 2 时，Selkies extended-desktop 路径直接请求 5120×2880，Xvfb 拒绝后保留旧 2048×1536。普通窗口与 DPR 2 的较小窗口通过，不能代替边界通过。

证据：私有 `infra/sealskin/runtime/r6n-auto-20261001/client-installed-max/`；候选 image `84dfce28cfb1…`。线上未部署、原浏览器不受影响。

处理：在精确摘要的 Selkies 布局计算路径按 MAX_RES 同比限制实际布局、捕获和输入所用尺寸；保持固定模式默认行为。新镜像须重验超限后的屏幕、点击输入和重连，并保留原失败。

修订实测：`e7e71db14431…` 的七组真实客户端矩阵全部通过，包含超大 Retina 窗口被限制到 3840×2160 后的实际画面定位、点击输入和重连。修复同时同步后端布局/广播尺寸，以及前端 canvas 尺寸/输入映射；此前仅修改后端的两轮失败继续保留。状态：已解决并部署。
