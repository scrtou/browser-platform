# DEV-016 · 公共递归前端的多个缓存期限

状态：已解决（工具与限定环境的公开验收；不保证公共前端只有一个缓存期限）。关联工作项：[R5C2](../work-items/R5C2-2026-09-14-approved-dns-ttl.md)。

预期仍为真实公开递归缓存与 TTL：权威发布新地址后，缓存阶段必须返回旧地址及可核对的剩余 TTL；过期阶段必须返回新地址。网页、解析路径、冻结代次及无回退证据另行核对。

实际发现：公开工具只采集每路径一次递归回答，默认前后回答来自同一个缓存期限。`1.1.1.1` 的实际回答存在不同期限；固定 UDP 源端口和请求报文也未固定期限。独立诊断还记录了 `8.8.8.8` / `9.9.9.9` 的期限差异，并未改变正式计划的批准解析器。`public-run-1` 的缓存阶段返回了部分新地址；预热后的 `public-run-2` 全部浏览器与地址轮换通过，但 DIRECT 单样本的到期区间相差约 0.6 秒，原 verify 正确拒绝其“同一期限”的结论。不能由一个数值前端地址推定只有一个缓存实例，也不能放宽取整误差掩盖该差异。

处理选择：扩展验收工具，新增显式绑定样本数的计划版本 2 / 证据版本 3；旧计划和证据的单样本规则保持。新计划的每阶段、每路径完整采集固定数量回答，逐条复核 wire、地址、解析器、来源、时序和 TTL。每一条 cached 回答都必须与至少一条实际 before 回答的到期区间相交，仍只允许原有的一秒取整；cached 必须整体早于所有初始期限，expired 必须整体晚于所有初始期限。任何无法匹配、变成新地址、缺失或损坏的样本使整轮失败，不能任选通过记录或丢弃异常回答。

这只匹配观测到的缓存期限，不声称识别了公共服务商的内部缓存实例。公开委派、真实浏览器三路径、代理冻结与失败/恢复条件保持。两个旧轮次及诊断完整保留，不能补造样本或按新模式追认；新模式使用新的随机名称、端点包、独立 QA 和验收记录。

多样本工具的 50 项检查通过，第三轮 32 样本仍发现缓存阶段的新地址，整轮保持失败。后续采用独立 Unbound 1.17.1 标准递归缓存，实际访问公网根、父区与公开权威；无 hosts、stub/forward zone、TTL 合成、预取或过期回答。固定依赖包和独立复制库在受限 QA 容器中运行，未安装主机系统包。新的随机名称、批准解析器身份和数值地址写入第四轮计划，复用原单缓存严格期限校验；这限定了验收环境，不宣称公共服务商前端具有单一缓存。

QA 53 入口按精确 A 名称及 RD 位选择回环 Unbound 或原 CoreDNS 权威后端，拒绝区外和区域传送。回环已通过真实递归、权威、拒绝、24 并发与有界超时检查。CoreDNS 初次因丢弃二进制所需的 `NET_BIND_SERVICE` bounding capability 无法执行，已核对原配置并修复；低端口 Python 入口先绑定，再永久降至 UID/GID 1000 并验证有效/允许/ambient capabilities 均为空。原部署失败、只读配置权限调整和降权复测单独保留。这是切换前的历史检查；后续公网验证和各轮结论见下方最终复核。

最终复核：第四轮因独立的 NS 白名单问题失败（DEV-017）；第五轮在标准 Unbound 上完成三个路径的 before/cached/expired，180 秒真实 TTL 使用原一秒取整规则通过。10 次缓存未命中与 dispatcher/CoreDNS 日志对应，66 次 DIRECT DNS 和 180 次外部代理解析/连接分别关联；13 个真实浏览器页面、故障/恢复及新代次端点切换通过。完整结果见 [公开验收](../../infra/sealskin/approved-dns-ttl-acceptance-2026-09-14.md#第五轮公开验收)。临时递归设施已移除，原权威恢复并通过本机/外部复测。

证据根为被忽略的 `infra/sealskin/runtime/r5c2-dns-ttl-2026-09-14/`，含前三轮失败、诊断、50 项工具检查及 `public-browser-5/correlation-2/result.json`。旧失败没有按新环境追认为通过。采样说明、设计/规格、工作项、验收与进度/计划已同步。
