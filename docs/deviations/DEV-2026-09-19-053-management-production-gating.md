# DEV-2026-09-19-053 · 管理面生产启用缺少无损首管理员升级与能力门控

状态：已解决（生产安全子集已启用，完整能力仍待 R6F）。关联工作项：[R6F](../work-items/R6F-2026-09-19-release-combination.md)。

## 预期

R6 管理面部署前，现有入口账号可在不更换密码、不改变授权的情况下明确升级为首个管理员；尚未配置控制器管理补丁、独立 SealSkin 管理身份或环境目录时，页面只展示已经可用的列表、账号、修改、停用和安全关闭能力，不展示必然失败或不能安全回退的新增、删除、代理及自定义指纹操作。

## 实际事实

- `profile-accounts` 原候选只允许在 `put --replace` 时携带角色，这会同时要求新密码并替换授权；直接编辑 version 2 账号表不符合受控运维要求。
- `profile.Service` 始终实现创建/删除方法，因此 HTTP 层的接口断言不能反映 `environment_catalog`、独立管理员客户端和 Home 归档端点是否实际可用；未配置时页面仍显示新增与删除表单，提交后才失败。
- R6F `candidate-8` 只绑定二进制和摘要，未包含上述生产能力门控，不能直接作为生产管理面包安装。

## 影响与处理

实现独立的账号角色修改 CLI，复用账号表锁、最后管理员保护和原子写入，不读取或替换密码；管理服务公开只读能力状态，HTTP 页面和写入口均按实际配置门控。完成 Go/race 回归和生产候选重建后，首轮生产只启用列表、角色/账号、名称与起始页修改、停用/启用和安全关闭；新增/删除、代理和自定义指纹在控制器补丁、独立管理员身份、目录与回退材料完整前保持关闭。

不得把首轮受控启用记为全部 R6 管理能力已经部署；真实客户端和后续完整能力仍由 R6F 分项记录。

## 结果

2026-09-19 使用重建的 `candidate-9` 完成生产受控启用：全模块 test/vet/gofmt 与 checks 镜像 race 通过；Adapter 配置只增加私有 `profile_directory`，首次无损导入 Personal/Work。现有 `owner` 通过新 CLI 从 version 1 普通账号提升为 version 2 `admin`，密码校验值、两项 Profile 授权和启用状态保持不变。切换前后生产容器 ID、启动时间、镜像及两个 Profile 的 operation/Session/资源计数一致，health/ready 为 200。

生产页面和写入口均按配置门控：列表、账号、名称/起始页、停用/启用和安全关闭已启用；创建/归档删除、代理草稿与自定义指纹作业保持不可见且直接请求返回 404。旧二进制、配置、状态和 version 1 账号表已保存在忽略目录作为组合回退材料；由于旧 Adapter 不支持 version 2 账号表，回退必须同时恢复旧账号表。Mac/Trilium 实测尚待用户确认，不属于本偏差的代码缺口。
