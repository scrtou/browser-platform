# DEV-018 · 重启抓包误把 MAC 当作冻结绑定

状态：已解决（记录器与同代次补验）。关联工作项：[R5C2](../work-items/R5C2-2026-09-14-approved-dns-ttl.md)。

预期：在专属 QA 网桥持续记录 Relay 重启、故障及同代次恢复的出站；冻结的是代理端点和代次资源，不要求 Docker 网卡 MAC 不变。

实际：第五轮 TTL、四协议网页切换、旧代理故障、离线恢复拒绝及在线同代次恢复均已取得对应证据；网桥记录器收尾时因 MAC 变化拒绝通过。网络仍只有同一 Relay，IPv4 不变，Docker 29 在重建连接后分配了新 MAC。原 IPv4 抓包实际记录了多个 MAC，但 IPv6 过滤只识别初始 MAC，不能据此声称完整跨重启观测。失败、容器/网桥身份及原始记录保留在 `public-browser-5/resume-1/`；该抓包仅标为 PARTIAL。

处理选择：修复观测，不改变产品或 DNS 条件。记录器只绑定准确归属、仅连接该 Relay 的 QA 网桥，以内核包类型区分从 Relay 进入网桥的帧和主机送出的帧，记录全部收到的 IPv4/IPv6 L3/L4 元数据及 MAC；不再以初始 MAC 丢弃 IPv6。核对源 IPv4、固定代理目标、两端网络归属和独占连接，保留 MAC 变化作为事实。用同一仍冻结的第五轮代次补测重启、故障/恢复，所有旧失败保留；采样阶段未改写或重跑。

复核：独立 internal 网络的四项实际 IPv4/IPv6、变化 MAC 和内核方向检查通过，测试资源已清理。同一冻结代次的 `transition-recheck-1/` 完成 Relay 重启、旧端点故障、离线 resume 拒绝、在线恢复和浏览器检查，网桥记录 46 条流量；后续新代次记录 26 条，两窗口均无禁止出站。旧 `resume-1/failure.json` 和原始 IPv6 不完整记录继续保留为 PARTIAL，未修改已通过的 DNS 阶段。抓包工具、工作项、索引、公开验收与进度已同步。
