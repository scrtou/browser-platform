# DEV-165 · 全新管理QA未在自身授权变化后重新登录

状态：已解决（R6AX范围）。关联[R6AX](../work-items/R6AX-2026-10-03-v1-release.md)。

第五个全新实例已通过最终不可变包安装、HTTPS初始化页、自定CLI管理员、登录/改密码和4/2/24内置删除保护。管理QA创建第一个浏览器时同步给当前管理员增加使用授权，第二次创建收到401；目录已有一个浏览器，没有启动Worker，也没有丢失首次创建。

[账号摘要与重载](../../adapter/internal/access/gateway.go)明确把profiles纳入accountHash，账号授权改变会撤销原登录。原QA在同一登录中连续创建且每次改变自身授权，未重新登录，和既有撤销契约不符。选择修订QA，在每次授权变更后重新登录；保留第一轮已通过检查、401与已创建对象，用独立attempt继续创建剩余对象并验证授权。不得关闭撤销保护、删除已创建对象伪造空实例，或把原失败结果改写为PASS。

最终验收须分别引用首次初始化/删除保护检查和后续管理通过记录；安装回执与程序包不变。产品代码及三浏览器镜像无需因此修改。

最终验证：第五实例首次初始化、改密码及删除保护检查保持原记录；initial-attempt2重新登录后保留首个对象，完成其余两个浏览器创建与全部使用授权，三个对象均无运行资源，QA服务已停用。最终报告明确引用这两段检查，原401没有改成通过。见[R6AX验收](../../infra/sealskin/r6ax-v1-install-acceptance-2026-10-03.md)。
