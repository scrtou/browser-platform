# DEV-067 · 统一代理目录变更缺少完整幂等与并发边界

状态：已解决（未部署候选）。日期：2026-09-22；复核日期：2026-09-23。
关联：[R7C](../work-items/R7C-2026-09-21-network-profile-catalog.md)、[R7 方案](../browser-workspace-plan.md)、[现行管理面规格](../specs/proxy-environment/management.md)。

R7C 最终收尾复核发现三处候选实现与既定边界不一致：`disable` / `revoke` 的 HTTP 表单虽强制提交幂等键，服务层却未持久化或使用该键，重复请求仍会增加目录修订和审计事件；绑定、停用、撤销分别读取状态与引用，没有共享串行化边界，可能在“撤销已判断无引用”与“绑定写入引用”之间交错；R7 方案要求创建、探测、停用、撤销和绑定均近期确认密码，候选只对停用、撤销和绑定执行该门槛。

影响限于尚未部署的 R7C 候选。生产未启用 `network_profile_catalog`，没有代理目录、Secret Store、浏览器绑定或真实凭据因此发生变化。

决定：不降低设计或验收。目录审计持久保存操作者范围的变更幂等键，同键同操作直接返回且不重复撤销，不同目标/动作复用同键返回修订冲突；统一代理变更互斥覆盖创建、探测、绑定、停用和撤销，使引用核对与状态迁移线性化；管理入口对上述敏感写操作统一要求近期确认密码。`network_profiles_test.go` 已覆盖重复停用/撤销、跨动作键冲突和绑定与撤销并发串行；`manage_gateway_test.go` 覆盖真实网关下创建/探测的近期确认密码门槛。2026-09-23 全量 Go test/vet 与关键包 race 复核通过；R7C 原“待新增回归”说明已过期，本偏差按未部署候选范围解决。
