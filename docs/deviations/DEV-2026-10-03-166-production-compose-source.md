# DEV-166 · 整理后的Compose示例仍被旧生产重建链引用

状态：已解决（R6AX范围）。关联[R6AX](../work-items/R6AX-2026-10-03-v1-release.md)。

生产部署前的只读Compose解析失败，尚未替换程序或容器。R6AX把仓库compose.yml整理为需显式实例变量的组件示例，但现有生产容器的config_files标签仍指向同一路径；原生产依赖旧PoC基础文件及后续覆盖层。新安装器生成独立Compose文件不受影响，不能把新示例直接作为存量实例重建输入。

选择为存量生产保留Git中上一版本的原基础Compose文件于私有维护目录，用该明确固定文件替代重建命令中的首层路径，其余覆盖层及顺序保持。解析后的完整有效配置必须与R7G1留存的最后部署配置一致，再允许只改控制器镜像；同时核对实际容器挂载/端口/环境/重启与日志配置。后续重建按新容器config_files标签及本次私有回执执行，不能回到缺少变量的新示例。回退保留固定基础文件和原镜像覆盖层，不覆盖业务状态。

这属于存量部署输入与通用示例的区分，最终程序包、新安装器和浏览器镜像不改变。需完成有效配置核对、生产保护部署及运维说明更新后收尾。

第二次切换的真实Chromium公开入口通过，但新增Env列表逐位置比较失败，保护快照一致后已再次回退。镜像默认环境完全一致；下一次核对拒绝重复变量名，并比较完整键值集合，不把环境列表序列当成变量语义，同时保存切换前后完整inspect供复核。端口、挂载、命令、重启与日志配置继续精确核对，不放宽任何环境值要求。

最终验证：生产最终使用固定Git基础文件和原覆盖链，有效配置与上次R7G1发布记录逐项一致后只改镜像；实际环境变量完整键值集合（拒绝重复名称）、启动命令、工作目录、用户、端口、挂载、重启及日志配置保持。第三次切换成功，原前置解析失败、环境顺序检查失败与两次回退均保留。后续按production-compose-command-attempt3.json及容器config_files执行，固定基础文件不得删除。见[R6AX验收](../../infra/sealskin/r6ax-v1-install-acceptance-2026-10-03.md)。
