# DEV-2026-09-27-072 · 动态域名端点租约扩展

状态：实现及部署已由 R7G1 完成；供应方自然漂移认证与新 GUI 热切换观察仍未测，不作为用户本次授权发布的门槛。发现日期：2026-09-27。

## 预期

现有代理规格要求 `proxy_required` 在一个浏览器代次内冻结已解析的数值 IPv4，Guard 仅允许该地址；更换代理修订需停止实例并重新启动。

## 实际事实

动态 DNS 上游的合法运营语义是域名保持不变而 A 记录按 TTL 变化。若继续把首次解析永久冻结到同一 Relay 代次，地址漂移会造成既有浏览器代次的代理失败，并触发恢复提示。

## 处理决定

新增显式的动态上游实现路径：仅当 `proxy_required` 的 `upstream_host` 不是数值 IP 且 enforcement 镜像声明支持 `dynamic-upstream` 时启用。该路径不把域名直接交给 Worker，也不放宽默认拒绝：控制器持有批准 DNS、TTL 和代次状态；每次切换先预探测候选地址，Guard 只在短暂原子过渡中允许旧/新集合，Relay 通过不可变 lease ID 和递增 revision 为新 TCP 连接选择新 IPv4；真实代理探测成功后仅保留新地址，任何失败回滚旧 lease/规则并保留阻断。数值 IP、DIRECT 和未声明能力的镜像维持旧静态模式。

## 影响与后续

规格、设计和组件文档已明确这是动态域名的可选扩展；“已运行连接不迁移、新连接使用新 lease”已在隔离候选中验证。公开域名已只读观察到供应方自然漂移且新端口可达，但未进行代理认证或客户端流量；生产部署仍需具备合规 QA 客户端与授权凭据后完成端到端 QA，并需明确运行边界；nft 实机过渡、失败注入/回滚和新旧连接切换已在隔离环境完成。本项不自动修改 R7F 生产发布。
