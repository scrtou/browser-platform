# 磁盘与构建材料保留

[容量策略](capacity-policy.md) · [运维说明](operations.md) · [缓存工具](../infra/maintenance/README.md)

容量准入按机器资源自动推导；磁盘治理不通过下调启动保护线解决空间不足。清理后至少保留当前 `min_free_disk_mib` 加 1024 MiB 的工作余量。现有监控每分钟采样磁盘，连续低余量报警；报告数字不等于允许删除的材料清单。

| 材料 | 保留与清理规则 |
| --- | --- |
| 新任务 Go/Python 编译与测试缓存 | 使用任务独立目录；小型任务优先可执行 tmpfs。所有相关进程退出后按精确路径回收，保留日志和测试结果 |
| 历史 Go 编译缓存 | 已收尾或已暂停构建后方可清理。7 天以上优先审查；较新的缓存只有在对应工作明确停止构建时纳入。必须核对标准标识、内容布局/摘要、无符号链接、无活动编译及无任何 Docker 挂载 |
| 依赖离线包、源码与未发布候选 | 保留，使冻结候选可重放；不能把 Go 模块依赖包当作编译缓存 |
| 当前与上一部署二进制、冻结源码、正式版本包 | 至少完整保留当前及上一版本的回退材料；更老材料归档/去重前逐文件校验并更新引用，不按修改时间自动删除。采用硬链接的产物只能原子替换，禁止原地覆写 |
| 验收报告、输入清单、作业状态、操作与发布日志 | 保留追踪链；未完成任务、失败记录和删除/撤销标记不得作为缓存清理 |
| Home、配置、凭据、指纹产物、恢复备份 | 保留。只有完成独立备份及恢复验证，并有明确数据保留决定后，才另立维护工作处理旧副本；本规则不自动删除这些数据 |
| Docker 镜像、卷及构建层 | `system df` 的 reclaimable 仅用于盘点。核对当前服务、冻结版本和恢复依赖后单独处理；不能运行通用 system/volume prune |
| 应用日志与监控历史 | 沿用已部署 Docker 每文件 10 MiB/3 文件、监控 14 天/2000 条限制；共享 journald 预算需要明确整机范围，项目清理不擅改其他应用 |

日常流程：查看只读容量诊断和监控 → 定位增长目录 → 建立维护工作项/保护快照 → 生成精确清理清单 → 执行并记录结果 → 核对真实数据、服务与剩余容量。不可读目录保持未知，不能统计为零或擅自更改权限。

R6AN 对历史缓存的执行结果见 [验收](../infra/sealskin/r6an-disk-retention-acceptance-2026-10-02.md)。本政策不部署定时删除任务；自动监控与人工审核清理各自有独立边界。
