# R2A · 旧生产部署的加密备份与维护准备

状态：已收尾。开始日期：2026-09-15。结束日期：2026-09-15。

## 目标与范围

在 [R5D](R5D-2026-09-14-entry-authentication.md) 正式收尾后，按 [R2](../roadmap.md#r2) 优先核对生产恢复前置条件。本项交付可在维护窗口使用的旧部署加密备份工具、只读运行快照和更新后的管理员说明；不停止生产浏览器、不重启服务或主机、不复制运行中真实 Home。

现有 `secure-backup.py create` 面向 FileSecretStore 和完整冻结环境；生产没有 Store，两个现存 Worker 也早于当前应用定义。不能创建伪造的 Store/验收报告以满足旧工具参数，也不能用明文 `backup-home.py` 代替正式备份。差异见 [DEV-037](../deviations/DEV-2026-09-15-037-legacy-encrypted-backup.md)。

## 实施与调用链

1. 只读核对当前 Adapter journal/控制 socket → Docker Home 挂载及实际 image ID → 当前应用/策略与输入摘要，生成无秘密内容的运行快照。区分正在运行的旧镜像与应用定义中的下次启动版本。
2. 增加明确的旧部署加密备份入口，复用 age 流式加密、tmpfs 完整认证、成员/摘要/路径/类型校验和新目录恢复。现有 Store 格式及撤销合并保持，旧模式不能用来绕过 Store、密封 Session 或入口账号的保护。
3. 只在 Profile 已经通过原生命周期停止且输入与快照匹配时收集 Home、身份、控制状态、旧凭据和必要配置。未冻结的旧环境记录实际运行事实，不伪造 E 组成功产物；恢复保持离线，不自动启用旧授权或启动 Worker。
4. 更新管理员备份/linger/开机说明，准备具体维护输入。真实 Home 备份/恢复、退出登录、整机重启和 Debian 13 继续归 R2，目标 Mac 与实际迁移归 R4B。

## 完成条件与验证

- 无 Store 的旧部署可用真实 age 完成加密往返，数据、API 身份、凭据及实际镜像引用保持；不输出秘密。
- 运行中、输入/绑定漂移、错误快照、错误恢复 identity/密文、危险成员和既有目标均拒绝；不写入真实数据或覆盖恢复目标。
- Store/入口登录/密封状态不能降级走旧模式；原 37 项备份及相关包装回归通过。
- 生产只读快照可生成，五份原配置/绑定与四容器保持；QA 临时资源清理、文档/语法/链接/敏感扫描完成。
- 更新组件、规格/运维、偏差/验收索引、进度/计划、父 R2 和本工作项后收尾。此子项不以工具可用代替真实生产恢复验收。
