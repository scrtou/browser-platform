# R6J · 监控、告警与日志保留

范围：沿现有本机只读健康接口增加周期监控、资源阈值、连续失败告警和恢复事件、严格字段白名单及有界保留；提供用户级定时单元与可复现验证。现有 Docker json-file 未配置大小上限，给出显式候选配置和验证，既有生产容器不因此重建；不删除生产日志/数据，不向外部人员发送通知。

代码地图：控制 socket GET /profiles/{id}/health 的 CachedOnly 分支 → HealthReport 的 overall/stale/expires_at → 独立只读监控器。主机资源来自 /proc/meminfo 与 statvfs；本地状态/事件独立归属，原应用日志和业务 journal 不触及。

完成条件：健康、过期/不可达、资源不足、连续失败/恢复和重启续接有可追溯事件；错误和敏感字段不进入监控输出；历史按时间/条数/大小有界，私有权限及并发执行保护；隔离故障回归、实际只读一次采样与生产保持核对。周期启用、Docker 日志策略是否已部署分别记录，不把配置文件等同线上生效。

验证：独立 Unix HTTP fixture 与时间/资源输入覆盖故障/恢复/保留/并发；实际生产接口仅 GET 缓存健康，不强制探测或启动停止浏览器。日志策略在独立空容器验证，固定本地镜像，不改 daemon 全局配置。

文档：组件 README、监控/日志运维说明、规格 S06 边界、验收索引、工作项与进度/路线图/完整计划表。R7G 缺证及客户端暂缓保持。
