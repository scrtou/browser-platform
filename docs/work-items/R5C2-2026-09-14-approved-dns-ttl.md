# R5C2 · 批准解析器、公开 DNS 与真实 TTL

状态：已收尾（候选代码、私有/公开 QA、资源清理和文档复核通过；未部署生产）。开始日期：2026-09-14。结束日期：2026-09-14。

## 目标与范围

- 对应用户持续目标“按计划开发直到项目可发布”及 [R5](../roadmap.md#r5)。前置 [R5C1](R5C1-2026-09-14-direct-isolation.md) 已收尾，`closeout.json` 为 PASS；本项保留公开 DNS/TTL 的完整验收条件。
- 为代理端点的引导解析增加显式、固定数值地址的批准解析器；查询不使用系统 resolver、hosts 或未批准的回退。数值上游地址不执行 DNS。旧策略的规范化 SHA 和已存在代次保持兼容，旧系统引导解析不算批准解析器验收通过。
- 引导解析结果、使用的解析器、观测时间和 DNS TTL 与本代次一起保存；活动代次和 Relay 重启继续使用冻结端点，后续新代次重新解析。TTL 不能用作释放 Home 或自动改写运行端点的依据。
- 使用固定依赖和有界 DNS 报文解析，验证事务/问题、CNAME、完整 IPv4 地址集合、UDP/TCP 截断回退及总超时；失败不能创建 Worker 或切换未批准出口。
- 建立可重复的公开权威 DNS、递归解析路径、缓存/TTL 和端点轮换验收工具。分别验证 DIRECT 网站域名、代理端点引导解析及真实上游的网站解析，不混成一个“DNS OK”。公开委派和真实 TTL 仍须实际外部证据，私有夹具只验证代码路径。
- 使用独立 QA 用户/Home/网络和候选镜像，保留生产浏览器、绑定、真实 Home、既有改动及旧镜像。本项不部署生产，不修改生产域名解析或主机防火墙。

本项采用的实现契约：代理端点使用独立的 `bootstrap_resolver_id` / `bootstrap_resolver_ip`，两字段成对配置，端口固定为 53；DIRECT 禁止这些代理字段。空字段保持旧策略规范化字节与旧系统解析兼容路径，该路径明确标为 `legacy_system`，不能计入批准解析器通过范围。数值 IPv4 直接冻结，不调用 DNS。批准路径只向指定端点发起 A 查询，UDP 截断经校验后回退同端点 TCP；全部查询共用 5 秒预算，最多八次 CNAME 跳转，无应用缓存或系统回退。延续既有上游可在私网部署的契约，完整地址集合拒绝 loopback、unspecified 与 multicast，不把代理端点 ACL 改成 DIRECT 的公网网站 ACL。

新的代理代次保存与 Home、operation 和策略 SHA 绑定的来源、地址集合、选中端点、查询/回答时间与逐记录 TTL；最早到期时间由相关 CNAME/A 的接收时间及 TTL 得出。分配保存观测、Relay 配置和网络规则配置摘要，恢复/重接核对摘要及只读挂载。旧代次仍按原契约对账；没有 DNS 证据的旧代次不伪造 TTL。到期仅是历史解析观测，不触发热更新、重新解析或释放占用。安装器在任何应用文件修改前核对固定 dnspython 版本与导入，镜像构建校验 wheel 散列，构建标签同时覆盖准备器、安装器、依赖锁与 patch。

最终 Runtime 为 `0.3.2-dns-v1-742b67ce9ba53575-pkg-ba7da090ed8a`。固定 dnspython 2.8.0 与临时 pip 25.3 wheel，Runtime 不执行 apk 或向系统安装 pip；实测 APK 数据库摘要/Python 版本与基础镜像一致，56 个准备文件逐字节重现。20 个应用文件与实际 QA 控制容器、source 和最终 manifest 对应；镜像摘要、完整结果及历史轮次见 [阶段报告](../../infra/sealskin/approved-dns-ttl-acceptance-2026-09-14.md)。
