# R6W · 新建浏览器复用已有认证代理

状态：已收尾并部署（2026-10-01）。用户明确授权实现新建时直接选择已有代理；前项 R6V 已收尾。

## 范围与调用链

管理页 `manage.go` → `CreateBrowser` → 私有 Profile 创建记录 → 控制器加密管理员接口 → Secret Store 精确追加授权 → 独立网络策略 → Home/应用安装。新建选择 accepted 代理，认证凭据不重新输入、不返回 Adapter。引擎/指纹联动及指纹数据 UI 保持。既有浏览器换代理的授权范围不扩大。

代码核对：UI 排除认证代理；初始绑定拒绝未冻结授权的新 ID；Secret Store 原版本的 grants 是 AES-GCM AAD，不能直接修改。选择增加按 owner/profile 定位的认证授权文件，保存完整 owner/profile/home/app、原凭据版本摘要及创建请求摘要，HMAC 认证且不可覆盖。仍引用同一凭据版本，因此撤销覆盖原授权与追加授权。创建先校验并持久化请求摘要/creating 记录，再执行授权；失败保留原请求，重试不能换参数。目录 allowed_profiles 只在控制器确认后追加，原 pending 导入冻结语义不变。

已有工作树大量修改全部保留。生产 Adapter R6V 949a645d…；控制器 R6J1 ad21dd6d…；R6I/R7G 未部署。私有证据根 `infra/sealskin/runtime/r6w-existing-proxy-20261001/`。
