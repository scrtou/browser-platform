# R6P · 指纹作业与显示配置分离

状态：已收尾（服务器实现、隔离验收与限定生产部署）。指纹与显示独立保存、组合完整验收后可用；目标 Mac/Trilium 新页面反馈及 R6O 缩放后续单列。

## 用户要求与范围选项

用户提出“指纹作业中的指纹和显示也应该分开”。已询问：独立可复用模板（建议），或只对现有作业页面分组。用户随后明确选择独立配置，并要求现在实施。

建议方案：指纹作业管理引擎/版本兼容性、语言、时区及所支持的设备参数；显示配置管理固定/自动屏幕策略、分辨率、窗口及 DPR 策略；纯画面保持比例/铺满仍属于显示偏好。当前未开放的字体/GPU 等字段不因设计分类而宣称可编辑。

独立配置不表示屏幕尺寸不属于网站可观察指纹。配置来源只保留一份，应用时组合并验证网页 screen/avail/inner/outer/DPR 与显示策略一致。指纹来源可复用，最终可运行产物仍绑定两份配置的精确修订、兼容引擎/版本及验收证据；改变显示不得重新随机生成无关种子或设备参数。

## 已核对的调用链

- adapter/internal/httpapi/manage.go：jobs 表单提交 screen_width/height、window_width/height，隐藏 dpr=1；表单提示生成完整产物，目前自定义作业仅 Camoufox 固定版本。
- adapter/internal/profile/environment_jobs.go：校验固定 DPR1、窗口不超过屏幕；写入包含 screen/window 与 fixed-screen/fixed-dpr 能力的环境规格。
- infra/camoufox/environment-job.py：隔离生成、完整验收，追加绑定 screen 元数据的 accepted artifact。
- template_catalog.go：指纹/显示组合按显式兼容表验证；当前分开的下拉仍引用完整环境，并未实现指纹源和显示策略独立组合。
- R6N/R6O：Chromix 已有固定/自动与系统 DPI 不同产物；不能据此声称 Camoufox 作业支持相同能力。

## 完成条件（独立模板方案）

1. 作业、存储、API 和界面有明确的指纹源/显示策略版本，不重复填写屏幕参数。
2. 同一指纹源配两种支持的显示策略后，无关指纹参数和持久种子保持；支持能力按引擎明确列出，不兼容组合拒绝。
3. 旧作业、旧产物、真实 Home、模板历史和未完成日志可继续读取，不自动重建运行实例。旧完整产物按旧契约保留，迁移策略须先设计与验证。
4. 在独立 QA 验证生成、组合、页面观测、输入坐标、重建/回退及失败保留；只有被验证的组合可应用。
5. 显示偏好的保存位置单独明确，保留用户希望跟随远程浏览器的要求；R6O UI Scaling 百分比尚未实现跨客户端统一保存，不能遗漏或冒称完成。
