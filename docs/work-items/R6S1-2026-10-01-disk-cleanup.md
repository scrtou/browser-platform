# R6S1 · 磁盘缓存清理

状态：已收尾。开始及结束日期：2026-10-01。

## 目标与范围

用户要求“先清理磁盘”。本项是 [R6S](R6S-2026-10-01-shared-display-templates.md) 的前置维护，暂不继续功能实施或发布。初始根文件系统可用约 547 MiB，使用率 100%；inode 未耗尽。

只回收 Docker 闲置构建缓存，必要时清理可再生成的 Go 编译缓存。保留全部镜像、容器、网络、数据卷、真实 Home、配置、账号、会话绑定、作业、发布/恢复材料及失败验收证据；不清空日志，不重启服务。

完成条件：释放至少 5 GiB 或使可用空间达到 5 GiB；核对 Docker 镜像/容器身份与挂载、数据卷/网络清单、配置/状态/生产作业摘要保持；记录实际可用空间及未处理占用。缓存将来按原输入重建，不以现有缓存作为唯一恢复材料。

## 阅读与实际入口

已读进度、路线图、工作流程、背景、架构、运维、监控组件和 R6J1/R6R 验收。磁盘由 `df` 与 `du` 核对；缓存由 `docker system df` / `docker buildx du` 核对，实际删除仅通过 BuildKit prune API。Docker 镜像、卷和容器的“reclaimable”不作为数据可删的依据。监控 `monitor.py:resources` 使用 statvfs 可用块，默认磁盘告警阈值 4096 MiB。

维护前工作区已有 95 项已跟踪修改、174 项未跟踪条目，全部保留。当前有生产浏览器、一个 R6S QA Worker 及其他构建容器运行，不操作其生命周期。

## 实施与验证

先保存私有资源与配置/作业摘要，再按缓存闲置时间清理，随后比较保护范围和可用空间。详细记录保存在被忽略的 `infra/sealskin/runtime/r6s1-disk-cleanup-20261001/`。没有改动产品行为；如发现实际保护范围变化，先核对并记录，不直接宣称通过。

实际完成：只清理 BuildKit 闲置构建缓存，四次合计约 8.83 GB；执行前 312 MiB，执行后核对可用 6,862 MiB。既有 15 容器、36 镜像 ID/标签、14 网络、975 卷、20 份生产配置/状态/作业文件和 6,496 个 R6S 证据路径保持。同期其他项目测试新增 1 个匿名卷，已核对事件并保留；可用空间有并发写入波动。未清理 Go 缓存、镜像、卷或日志，没有重启服务。经核对未发现本次维护引入的设计偏差，详细结果见[验收](../../infra/sealskin/r6s1-disk-cleanup-acceptance-2026-10-01.md)。
